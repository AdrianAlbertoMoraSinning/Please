SAFE DEPLOYMENT ORDER
=====================
1) SUPABASE FIRST
   Run the complete file:
   supabase/STEP18_1_FINANCIAL_MASTER_DATA.sql

   Expected result:
   Success. No rows returned

2) VERIFY SUPABASE
   Run the complete read-only file:
   supabase/STEP18_1_VERIFY.sql

   Expected result:
   Every returned row must show status = PASS.
   Do not upload GitHub if any verification row shows FAIL.

3) GITHUB / NETLIFY
   Upload the files in this package preserving their exact folders.
   Replace files when the same path already exists.
   Do NOT delete any other repository file.
   Wait for Netlify to show Published.

4) SMOKE TEST BEFORE STEP 18.2
   - PLEASE Home loads normally.
   - Admin Dashboard loads normally.
   - Provider Portal / Provider Login remain available.
   - Service Request / Tracking / Payment remain available.
   - CAL Dashboard shows STEP 17 Accounting Engine normally.
   - CAL > Financial Master Data opens successfully.
   - Existing Customers appear as PLEASE-managed CUSTOMER parties.
   - Existing Providers appear as PLEASE-managed OPERATIONAL PROVIDER parties.
   - Operating Bank maps to GL 1000.
   - Stripe Clearing maps to GL 1090.
   - Creating a test Supplier does NOT create a Journal Entry.
   - Assigning SUPPLIER role to a PLEASE Provider does NOT change the Provider operational identity.

WHAT STEP 18.1 DOES NOT DO
==========================
No Purchases, Vendor Bills, new AP transactions, Refund posting, advanced Expenses,
Bank Reconciliation, Inventory transactions, Fixed Assets, Payroll, Period Close or
new STEP 17 accounting event types are introduced in this package.
